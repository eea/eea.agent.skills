## EEA document conventions

- `CHANGELOG.md` uses date-based versioning: heading `## YYYY-MM-DD — Title` with `### Added` / `### Changed` / `### Why` / `### Notes` sections. Keep new entries in that shape.
- `README.md` skill tables use the four-column layout (Skill / Description / Category / Upstream Source); keep table rows parallel and descriptions under one line.
- Skills in this repo follow the two-file overlay: upstream text in `src/skills/<name>/SKILL.md`, EEA deltas in `EEA-OVERRIDES.md`. The `skills/` output is generated by `scripts/build.sh`; never edit it directly.

## Commit messages and PR bodies

Treat them as briefings a reviewer reads in under a minute: lead with why the change exists, then what changed, then how it was verified. Never paste logs, SHA lists, or metric tables; link to them instead.
